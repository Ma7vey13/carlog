## Этап 4 — Шифрование и синхронизация: готово, ждёт приёмки

### Что сделано
- **Шифрование в браузере:**
  - AES-GCM 256, ключ из пароля через PBKDF2-SHA256 с 600 000 итераций, у каждого файла свой случайный IV;
  - `vault.json` содержит только открытые параметры и проверочную строку;
  - пароль не хранится нигде;
  - «Запомнить на этом устройстве» хранит неизвлекаемый ключ, а не пароль;
  - токен на устройстве лежит зашифрованным (D-051).
- **Мастер настройки** («Ещё → Настроить синхронизацию»):
  - репозиторий, токен, имя устройства → проверка, что репозиторий приватный и в него можно писать;
  - новый пароль с крупным предупреждением «Забытый пароль = потерянные данные» и галочкой «Я сохранил пароль» — или пароль существующего хранилища;
  - первое устройство создаёт `vault.json` в пустом репозитории и отправляет данные; второе подтягивает их.
- **«Отправить»** — один коммит по разделу 8. Если на GitHub есть чужие изменения, они сначала подтягиваются и сливаются. Если другое устройство отправило в ту же секунду, приложение повторяет попытку, до 3 раз. Сканы уходят зашифрованными, каждый один раз.
- **«Подтянуть»:** скачивает и расшифровывает снимок, сливает записи. Результаты Claude Code из `drafts/` превращаются в черновики «готов к проверке» — пригодится на этапе 5. Сканы на телефоне скачиваются, только когда их открывают; на компьютере можно включить «скачивать все».
- **Слияние:** для каждой записи побеждает более поздняя правка, удаление тоже считается правкой. При полном совпадении времени результат одинаков на обоих устройствах. Ничего не теряется.
- **Индикаторы в «Ещё»:** имя устройства, когда отправляли и подтягивали, сколько изменений не отправлено.
- **При запуске:** если на GitHub есть новые данные, появляется плашка «На GitHub есть новые данные» с кнопкой «Подтянуть». Сама она ничего не применяет.
- **Ошибки понятные:**
  - «Токен истёк или неверен» — с кнопкой «Ввести новый токен» и ссылкой на инструкцию;
  - «Пароль сменили на другом устройстве»;
  - «Нет связи с GitHub».
- **Настройки устройства:** заменить токен, забыть пароль на этом устройстве, отключить синхронизацию (данные остаются).
- **Инструкция `docs/04-sync.md`:**
  - как создать fine-grained токен только к `carlog-data` с правом Contents: Read and write;
  - настройка телефона и компьютера, что делать каждый день;
  - что делать, если токен истёк или пароль забыт;
  - что лежит в репозитории.

### Как проверить самому (приёмка этапа)
1. По `docs/04-sync.md`, шаг 1, создайте токен для телефона и отдельно — для компьютера.
2. **Телефон:** обновите приложение → **Ещё → Настроить синхронизацию** → вставьте токен → **Проверить доступ** → придумайте пароль и **сохраните его в менеджере паролей** → **Создать хранилище и отправить данные**.
3. **Компьютер:** **Ещё → Настроить синхронизацию** → свой токен → **Проверить доступ** → тот же пароль → **Подключиться**. Визиты с телефона появятся в «Истории».
4. Введите визит на телефоне → **Отправить**. На компьютере откройте приложение → плашка «На GitHub есть новые данные» → **Подтянуть**. Визит появится. Проверьте и в обратную сторону.
5. **Без синхронизации на обоих:** добавьте по визиту на каждом устройстве, не синхронизируя. Затем **Отправить** на одном, **Отправить** на другом, **Подтянуть** на первом — оба визита есть на обоих.
6. Откройте `carlog-data` на GitHub. Читается только `vault.json`; `data/snapshot.enc` и `scans/*.enc` — нечитаемые файлы.

Ожидаемый результат: данные совпадают на обоих устройствах, ничего не потерялось, на GitHub нет читаемых данных.

## Этап 2 — Модель данных, ручной ввод, история: готово

### Что сделано
- **База данных:** все сущности раздела 4 хранятся в IndexedDB (Dexie). У каждой записи есть служебные поля: `id` (UUID v7), `createdAt`, `updatedAt`, `deleted`, `deviceId`. У устройства свой постоянный id, сканы хранятся отдельно, только локально.
- **Встроенные данные:** машина (Hyundai Santa Fe New, 2.7 V6), настройки по умолчанию и 24 стартовых узла. id у них постоянные, поэтому при синхронизации они не задвоятся (D-025).
- **Ручной ввод визита:**
  - дата, пробег, сервис с реквизитами или «своя работа», заметки;
  - один или несколько документов: тип, номер, дата, связанный заказ-наряд, итоги из документа, «покупка без установки»;
  - строки: вид, название, кол-во, цена, сумма, узел, «запчасть клиента», позиция, бренд, артикул, единица.
- **Подсказки при вводе:**
  - сумма считается из количества и цены;
  - узел и позиция подставляются по названию;
  - видно, как название будет сохранено («Супорт» → «Суппорт»);
  - подсказки по прошлым названиям и сервисам;
  - шесть шаблонов;
  - «Скопировать прошлый визит».
- **Проверки при сохранении:** с понятными сообщениями, например «Строка 3: количество × цена не равно сумме» (D-031).
- **История:**
  - лента визитов и ручных отметок пробега;
  - поиск по названию с учётом падежей и опечатки «Супорт»: «колодки» находит и «колодок»;
  - фильтр по узлу, включая вложенные узлы;
  - под визитом показываются совпавшие строки.
- **Карточка визита:** документы, работы отдельно от запчастей и материалов, итоги, узел и позиция у каждой строки, исходное название из документа. Кнопки «Изменить» и «Удалить» с подтверждением; удаление ставит метку, а не стирает запись.
- **Отметки пробега:** «Отметить пробег» в «Истории», удаление с подтверждением. Отметка из визита создаётся и меняется вместе с визитом.
- **Справочник узлов** в «Ещё»: добавить, в том числе внутрь другого узла, переименовать, удалить.
