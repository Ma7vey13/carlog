## Этап 2 — Модель данных, ручной ввод, история: готово

### Что сделано
- **База данных:** все сущности раздела 4 хранятся в IndexedDB (Dexie). У каждой записи есть служебные поля: `id` (UUID v7), `createdAt`, `updatedAt`, `deleted`, `deviceId`. У устройства свой постоянный id, сканы хранятся отдельно, только локально.
- **Встроенные данные:** машина (Hyundai Santa Fe New, 2.7 V6), настройки по умолчанию и 24 стартовых узла. id у них постоянные, поэтому при синхронизации они не задвоятся (D-025).
- **Ручной ввод визита:**
  - дата, пробег, сервис с реквизитами или «своя работа», заметки;
  - один или несколько документов: тип, номер, дата, связанный заказ-наряд, итоги из документа, «покупка без установки»;
  - строки: вид, название, кол-во, цена, сумма, узел, «запчасть клиента», позиция, бренд, артикул, единица.
- **Подсказки при вводе:**
  - сумма считается из количества и цены;
  - узел и позиция подставляются по названию;
  - видно, как название будет сохранено («Супорт» → «Суппорт»);
  - подсказки по прошлым названиям и сервисам;
  - шесть шаблонов;
  - «Скопировать прошлый визит».
- **Проверки при сохранении:** с понятными сообщениями, например «Строка 3: количество × цена не равно сумме» (D-031).
- **История:**
  - лента визитов и ручных отметок пробега;
  - поиск по названию с учётом падежей и опечатки «Супорт»: «колодки» находит и «колодок»;
  - фильтр по узлу, включая вложенные узлы;
  - под визитом показываются совпавшие строки.
- **Карточка визита:** документы, работы отдельно от запчастей и материалов, итоги, узел и позиция у каждой строки, исходное название из документа. Кнопки «Изменить» и «Удалить» с подтверждением; удаление ставит метку, а не стирает запись.
- **Отметки пробега:** «Отметить пробег» в «Истории», удаление с подтверждением. Отметка из визита создаётся и меняется вместе с визитом.
- **Справочник узлов** в «Ещё»: добавить, в том числе внутрь другого узла, переименовать, удалить.
- **Проверка владельцем:** сценарий «Как проверить самому» пройден на живом сайте (во встроенном браузере, по просьбе владельца): ввод визита со стр. 4, поиск «колодки», правка цены, удаление — всё работает.
- **Найдено и исправлено при проверке:**
  - карточка визита не предупреждала, что итоги документа разошлись со строками после правки цены (D-037);
  - подсказка про офлайн закрывала кнопку «Сохранить визит» (D-033);
  - дата документа не следовала за датой визита (D-026);
  - смоук-тесты молча проверяли старую сборку (D-034).

### Как проверить самому
1. На компьютере или телефоне откройте https://ma7vey13.github.io/carlog/. Если внизу появится «Доступна новая версия», нажмите **Обновить**.
2. **История → Добавить визит.** Введите визит со стр. 4:
   - дата 12.03.2025, пробег 293000, сервис;
   - тип «Акт выполненных работ», номер 1, «К заказ-наряду №» 25857;
   - кнопками **+ Работа / + Запчасть / + Материалы** добавьте 7 строк и для каждой введите название, кол-во и цену. Сумма посчитается сама.
3. Откройте **Итоги из документа** и введите 4700, 18500, 23200. Сообщения о расхождении быть не должно. Нажмите **Сохранить визит**.
4. В карточке итог должен быть 23 200 ₽, а строка «Супорт…» сохранится как «Суппорт…».
5. Вернитесь в **Историю** и наберите в поиске «колодки» — визит найдётся, под ним будут видны строки с колодками.
6. Откройте визит → **Изменить** → поменяйте цену → **Сохранить визит**. Затем **Удалить** → подтвердите.

Ожидаемый результат: визит сохраняется, находится по «колодки», правится, а после удаления пропадает из ленты.

### Тесты и сборка
- **Юнит-тесты (Vitest):** 124 пройдено, 0 упало. Покрыты деньги, даты, нормализация названий (все особые названия со страниц 1–6), подбор узла (30 строк со страниц 1–6), логика формы, поиск и база (на `fake-indexeddb`): заполнение, сохранение, правка, удаление, пробег, справочник узлов.
- **Смоук-тесты (Playwright, 360 px и десктоп):** 21 пройдено, 0 упало, 1 пропущен намеренно (как на этапе 1). Новые тесты:
  - весь сценарий приёмки: ввод визита по мотивам стр. 4 → поиск «колодки» → фильтр по узлу → правка → удаление;
  - шаблон, копирование прошлого визита, подсказки названий, выход без сохранения, отметка пробега;
  - справочник узлов.
- **Тестовые данные:** синтетические визиты по мотивам стр. 1, 2 и 4. Сервис в них вымышленный, личных данных нет.
- **Сборка:** без ошибок.
- **Вручную** просмотрены скриншоты формы, ленты, поиска, карточки и справочника на 360 px и на десктопе в тёмной теме.

### Известные проблемы и ограничения
- Если в один визит ввести и заказ-наряд, и акт по одному заказу, итог визита сложится дважды. Это решается на этапе 3 вместе с проверкой дублей.
- Подсказки названий используют стандартный выпадающий список браузера: на Android он появляется над клавиатурой после 1–2 букв.
- Дубли, «работа без запчасти», пробег против прогноза пока не проверяются — это экран проверки на этапе 3.

## Этап 1 — Каркас PWA и публикация: готово

Pages включён владельцем, сайт https://ma7vey13.github.io/carlog/ проверен на 360 px и на десктопе (открывается, работает без интернета, нет ошибок в консоли). Тег `stage-1`.

### Что сделано
- Проект на Vite 8 + React 19 + TypeScript 7, версии зависимостей зафиксированы точно.
- Навигация: Состояние · История · Входящие · Регламент · Ещё. На телефоне — нижняя панель, на широком экране — боковое меню. Адреса вида `#/history` работают офлайн и в установленном приложении.
- Пустые экраны с пояснением, что и на каком этапе там появится. Неизвестный адрес → «Страница не найдена» со ссылкой на главную.
- Светлая, тёмная и системная тема: переключатель в «Ещё», выбор сохраняется, нет вспышки при запуске. Цвет строки состояния Android совпадает с темой.
- PWA: манифест, иконки (синий спидометр, включая maskable для Android), работа без интернета, метка «офлайн» в шапке, подсказка «Приложение сохранено и будет открываться без интернета».
- Подсказка «Доступна новая версия» с кнопками «Обновить» и «Позже». При проверке нашлась и исправлена ошибка: при самом первом открытии кнопка «Обновить» ничего не делала (D-019).
- «Ещё»: сколько места занято, включено ли постоянное хранилище (запрашивается при первом запуске), версия и дата сборки.
- Content-Security-Policy: только свой сайт и `api.github.com`, без `unsafe-inline` и `unsafe-eval`.
- GitHub Actions: на каждый push — проверка типов, юнит-тесты, смоук-тесты, сборка; из `main` — публикация на Pages.
- Инструкции: `docs/02-github-pages.md` (включить Pages), `docs/03-install.md` (установка на Android и компьютер).

### Как проверить самому
1. Включите Pages по `docs/02-github-pages.md` и дождитесь зелёной галочки в **Actions**.
2. На компьютере: откройте https://ma7vey13.github.io/carlog/ в Chrome или Edge → установите по `docs/03-install.md` → пройдите по пяти разделам → в «Ещё» переключите тему.
3. На телефоне: откройте ту же ссылку в Chrome → дождитесь подсказки «Приложение сохранено…» → **⋮ → Установить приложение** → включите режим полёта → откройте «Бортжурнал» со значка.
Ожидаемый результат: приложение открывается по ссылке и со значка, без интернета показывает метку «офлайн» и все пять разделов.

- Вручную просмотрены скриншоты на 360 px и на десктопе в обеих темах; поправлены перенос подписи «Как в системе» → «Системная» и выравнивание заголовка на десктопе.
